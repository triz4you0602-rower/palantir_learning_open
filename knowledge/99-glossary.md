# 99 · 용어집 (Glossary)

핵심 개념을 영어 병기로 빠르게 참조. 상세는 각 문서 링크로.

| 용어 (KO) | Term (EN) | 한 줄 정의 |
|---|---|---|
| 전진 배치 엔지니어 | **FDE** (Forward Deployed Engineer) | 고객 환경 내부에 임베드되어 프로덕션 코드를 직접 짜는 풀스택 엔지니어. → [01](01-fde-model.md) |
| 델타 | **Delta** | FDE 중 소프트웨어 엔지니어 역할. 프로덕션급 코드·파이프라인·온톨로지 모델링. |
| 에코 | **Echo** (Deployment Strategist) | 도메인 전문가 출신. 미션 현실을 기술 요구로 번역, 채택·정치 담당. |
| 온톨로지 | **Ontology** | 조직의 디지털 트윈. "지저분한 현실의 지도." → [03](03-ontology.md) |
| 객체 타입 | **Object Type** | 현실 개체/이벤트의 스키마 정의 (≈ 테이블). |
| 링크 타입 | **Link Type** | 두 객체 타입 사이 관계의 스키마 정의 (≈ 그래프 엣지). |
| 행동 타입 | **Action Type** | 사용자가 데이터에 가할 수 있는 변경 집합의 스키마 정의 (거버넌스된 쓰기). |
| 함수 | **Function** | 온톨로지와 통합된 코드 로직. |
| 의미 계층 | **Semantic Layer** | 세계가 무엇으로 이루어졌는가 (개체·관계). |
| 동적 계층 | **Kinetic Layer** | 그 세계에서 무엇을 할 수 있는가 (행동·로직). |
| 자갈길→고속도로 | **Gravel Road → Paved Highway** | 특정 고객용 거친 해결책 → 반복 패턴 추출 → 재사용 플랫폼 기본요소. → [01](01-fde-model.md) |
| 그라운드 트루스 | **Ground Truth** | 문서가 아닌 현장의 실제 진실. 몰입으로만 얻음. |
| 하중 임시방편 | **Load-bearing Workaround** | 수년간 보이지 않게 시스템을 지탱해온 임시방편. 문제 발견의 핵심 단서. |
| 제품 발견 메커니즘 | **Product Discovery Mechanism** | FDE 현장 작업이 곧 팔란티어의 제품을 만들어내는 상류 활동. |
| 4대 플랫폼 | Gotham / Foundry / Apollo / **AIP** | 정보·상업 / 배포 / AI 계층. → [00](00-palantir-overview.md) |
| AI FDE | **AI FDE** | FDE 방법론을 자연어 에이전트로 부분 자동화. 변경은 Branch Proposal로 사람이 리뷰. |

### TRIZ 용어 (비교 문서용 → [10](10-triz-vs-fde.md))

| 용어 (KO) | Term (EN/RU) | 한 줄 정의 |
|---|---|---|
| 트리즈 | **TRIZ** (Теория решения изобретательских задач) | 알트슐러가 정립한 발명적 문제해결 이론. 문제를 모순으로 정식화해 축적된 해 모델로 푼다. |
| 기술적 모순 | **Engineering/Technical Contradiction** | "A를 개선하면 B가 악화된다" — 서로 다른 두 파라미터의 트레이드오프. |
| 물리적 모순 | **Physical Contradiction** | 하나의 파라미터에 상반된 두 요구가 동시에 정당하게 걸린 상태. 주로 **분리**로 해소. |
| 행정적 모순 | **Administrative Contradiction** | "개선해야 하는데 방법을 모른다" — 필요와 능력 사이의 미정식화 상태. ⚠️ 알트슐러 **초기 저작** 용어로, ARIZ-85C 본문에는 등장하지 않는다. |
| 미니문제 | **Mini-problem** | ARIZ 1.1. *"시스템에 최소한의 변경으로 (요구 결과)를 달성"* 하도록 문제를 재진술 — 목적은 **트레이드오프로 가는 길을 처음부터 차단**하는 것. |
| 작동 구역 / 작동 시간 | **OZ / OT** (Operating Zone / Time) | ARIZ 2.1~2.2. 갈등이 일어나는 공간과 시간(T1=갈등 중, T2=갈등 이전). IFR과 물리적 모순은 여기에 앵커링된다. |
| 창의적 인격 발달 이론 | **ТРТЛ / ЖСТЛ** | 알트슐러·베르트킨. 발명가와 **외부 상황**의 대립을 88단계 "체스 게임"으로 모델링한 별도 이론. ARIZ와는 통합돼 있지 않다. |
| 분리 원리 | **Separation Principles** | 물리적 모순 해소 5종: 공간 · 시간 · 관계(조건) · 방향 · **시스템 수준**. |
| 문제 식별 도구상자 | **Problem-identification Tools** | 기능-원가·흐름 분석 · CECA · 트리밍 · 특징 전이 · S-커브 · TESE. 목적은 *"증상이 아닌 근본 원인인, 숨겨진 옳은 문제"* 식별. |
| 인과사슬 분석 | **CECA** (Cause-Effect Chain Analysis) | 초기 결점 → **핵심 결점(key disadvantage)** 까지 인과 사슬을 세우는 TRIZ의 근본 원인 분석. 5 Whys·RCA와 같은 자리. |
| 모순행렬 | **Contradiction Matrix** | 39×39 표준 파라미터 표. 칸마다 추천 발명원리(총 40원리)를 통계적 빈출 순으로 제시. |
| 이상해결책 | **IFR** (Ideal Final Result) | 최소 변경·무악화로 문제가 완전히 제거되는 최선의 해 모델. 최종 상태에서 역산하는 장치. |
| 이상성 | **Ideality** | 시스템의 총 편익 ÷ 모든 대가 요소의 합. 진화는 이상성 증가 방향. |
| 아리즈 | **ARIZ** | 복잡한 핵심 문제를 잘 정의된 문제 모델로 변환하는 절차. 정본은 ARIZ-85В. |
| 물질-장 분석 / 표준해 | **Su-Field / SIS** | 문제를 물질-장 모델로 표현하고 76개 전형적 해 모델을 적용. |
| 진화 트렌드 | **TESE** (Trends of Engineering Systems Evolution) | 기술 시스템이 이상성 증가·상위시스템 통합 방향으로 진화한다는 패턴 집합. |
| 심리적 관성 | **Psychological Inertia** | 익숙한 심상·기성 해법에 닻내리는 경향. TRIZ 도구가 우회하려는 대상. |
